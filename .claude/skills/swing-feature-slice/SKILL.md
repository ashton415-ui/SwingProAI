# Complete an authorized premium feature slice

1. Confirm owner's exact local implementation grant, base branch/SHA, isolated worktree and allowed file paths. Refuse writes until authority exists. Read `CLAUDE.md`, Product Constitution, Launch Gates and subsystem docs.
2. Capture the golfer/coach journey from UI through API/worker/storage/results and acceptance matrix (positive, negative, accessibility, failure recovery, tenant entitlements and provenance). Do not silently omit required platform pillars.
3. Have the lead implement directly; use read-only subagents for architecture/security/QA/UX on complex slices, at most a few in parallel. Do not run multiple writers against shared files.
4. Run affected unit/type/lint checks, actual workflow integration and runtime lifecycle; record exact commands/exit codes. Run broader regression at candidate/release checkpoint, not reflexively after every line.
5. Correct defects within the **authorized** slice. Never commit, push, PR, merge, deploy or mutate DB/Stripe/Vercel/firewall without that action's required specific grant under canonical rules.
6. Return one clear report: base SHA, changed paths, tests RUN vs NOT_RUN, independent review findings, premium UX issues, risks, verdict and the next single approval.
